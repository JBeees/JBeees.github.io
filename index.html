Staying up when it gets busy

  

    

      
Type
Backend system

      
Built for
Cukurukuk team project, Universitas Brawijaya

      
Built with
Go, PostgreSQL, Redis, RabbitMQ, Nginx, Docker, Prometheus, Grafana

      
Code
JBeees/exploding-user-data-scalabilities

    

    

      
A simulation of a transaction system that doesn't collapse when millions of transactions arrive at once.

      
The problem. Picture a banking app on payday or during a big promo. Millions of people open the app within an hour, and an older system can jam. This project imitates that situation with a target of 1 million transactions per hour, based on a CIMB Niaga case study.

      
What I built. The work is split across three identical copies of the server. Users who get too aggressive are throttled, heavy jobs are handed off to a queue, and frequently requested answers are kept in fast memory. If one part misbehaves, it is cut off temporarily so the problem doesn't spread. Everything is monitored through a graph dashboard and tested with load tests.

      
The journey of one transaction

        
  1. A crowd of users arrives
  2. Load balancer picks a server
  3. Three identical servers work
  4. Queue and fast memory
  5. Saved in the database

      

    

  






  
Learning together without sharing data

  

    

      
Type
Distributed machine learning

      
Built for
Distributed Computing Systems coursework

      
Built with
Python, scikit-learn, TCP socket connections

      
Code
JBeees/federated_learning_project

    

    

      
Four computers train one shared prediction model, and none of them sends its raw data.

      
The problem. Student grade data is private, so it can't be gathered in one place. Yet to guess accurately, a model needs to learn from a lot of data.

      
What I built. Each computer learns from its own data, then sends only what it learned to a central server. The server averages those results and sends back a smarter version. After 10 rounds, the pass-or-fail prediction reaches an average accuracy of about 90.6%, using student grade data from the UCI Machine Learning Repository.

      
One round of learning

        
  1. Data stays on each computer
  2. Each computer learns on its own
  3. The server averages the results
  4. The new model is sent back

      

    

  






  
Turning messy data into insight

  

    

      
Type
Data processing

      
Built with
Python, PostgreSQL, SQL, Docker

      
Code
JBeees/online-retail-data-pipeline

    

    

      
An automated pipeline that cleans an online store's sales data and turns it into charts.

      
The problem. Raw sales data is full of problems, such as cancelled orders, empty fields, zero prices, and duplicate rows. Data like this is hard to use for making decisions.

      
What I built. One command runs everything. The data is read, cleaned, tidied into three tables, stored in a database, then turned into charts and answers to business questions. The data comes from an online store transaction dataset on Kaggle.

      
From raw file to chart

        
  1. Raw data file
  2. Cleaned
  3. Tidied into three tables
  4. Saved in a database
  5. Turned into charts

Type

Built for
Coursework

      
Built with

A site for tracking meals delivered to schools, complete with a map and reports.

      
The problem. When food is distributed to many schools across many regions, it's hard to know how many portions have arrived and whether the quality is good.

      
What I built. A site with a map showing the number of recipient schools, the number of students, portions delivered, and the percentage of good-quality meals. A simple app for tracking daily money, savings, and debts.

      
The problem. Allowances or salaries often vanish unnoticed because small expenses go unrecorded.

      
What I built. An app that keeps daily money separate from savings. Expenses are logged by category such as food, transport, and entertainment, and the balance drops automatically. Savings are locked with a 6-digit PIN. Weekly, monthly, and yearly summaries appear as bar charts, and there's a page for recording debts. All data stays on the phone and is never sent to the internet.

      
How the app is used

        
  1. Add balance
  2. Record an expense
  3. Balance updates automatically
  4. View the summary charts

      

    

  






  
A file downloader that can resume

  

    

      
Type
Desktop application

      
Built with
Python, PyQt6, browser extension (JavaScript)

      
Code
JBeees/python-download-manager

    

    

      
An app for downloading large files faster, and resuming if the connection drops.

      
The problem. Large downloads often fail halfway, forcing you to start over from the beginning.

      
What I built. Inspired by Internet Download Manager. A file is split into several parts (eight by default) that download at the same time, so it's faster. If the connection drops, the download resumes from the last part. There are pause, resume, cancel, and retry buttons, plus a download queue. An extension for Chrome or Brave can automatically catch downloads from the browser.

      
From click to done

        
  1. Link clicked in the browser
  2. Extension catches it
  3. File split into several parts
  4. Parts download simultaneously
  5. Merged into one file

      

    

  






  
A chatbot that gets what you mean

  

    

      
Type
Terminal chatbot

      
Built with
Python, Sentence Transformers (Hugging Face)

      
Code
JBeees/simple-cli-faq-chatbot

    

    

      
A Q&A chatbot that understands the meaning of a question, not just matching words.

      
The problem. People ask the same thing in different sentences. A chatbot that only matches exact words will fail to recognize them.

      
What I built. This chatbot turns a question into a series of numbers that represent its meaning, then finds the question in the FAQ list whose meaning is closest. If nothing is similar enough, it admits it doesn't know instead of making up an answer.

      
How the chatbot answers

        
  1. Question typed
  2. Turned into numbers that represent meaning
  3. Matched against the FAQ list
  4. Answers, or admits it doesn't know

      

    

  






  
Practicing cracking security puzzles

  

    

      
Type
Cybersecurity

      
Contents
More than 250 challenge folders

      
Built with
Python, C, Bash, PHP

      
Code
JBeees/CTF

    

    

      
A collection of notes and scripts from cybersecurity competitions I joined to practice.

      
What is CTF. Organizers hide a secret code called a flag inside a deliberately vulnerable system, and participants race to find it. The practice trains the attacker's way of thinking so I can defend better.

      
What I keep here. Challenges from picoCTF and CTFlearn, mostly digital forensics, meaning hunting for traces inside files and network recordings. There's also reverse engineering (working out how a program works), binary exploitation, web security, and cryptography. The contents are notes on solution steps and helper scripts.

      
One challenge, from start to flag

        
  1. Challenge given
  2. Investigating the file or system
  3. Finding the weakness
  4. Flag captured

The foundation of a blockchain network

  

    

      
Type
Private blockchain network

      
Built for
Coursework, split across four groups

      
Built with
Ethereum (Geth), Clique consensus

      
Code
JBeees/blockchain-skripsi

    

    

      
A private blockchain network set up as the foundation for a project shared by several groups.

      
What is a blockchain. A shared ledger that can't be quietly altered, because every computer on the network holds a copy.

      
What's here. Four groups build one shared system, covering smart contracts, a plagiarism detection engine, and a monitoring dashboard. This repository only holds the foundation: the initial network configuration with five validators, a new block every 5 seconds, and setup guides for each group. The other parts were built by other groups and aren't here.

      
Setting up the network

        
  1. Each group installs Geth
  2. Validator addresses are collected
  3. The genesis block is composed
  4. Computers connect to each other
